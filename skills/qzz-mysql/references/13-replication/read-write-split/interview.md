# 面试题

## Q1：读写分离架构下，怎么解决"写完读不到"的问题？

**考点**：这是读写分离最核心的坑。

**回答**：根本原因是主从复制有延迟。解决方案分几个层次：(1) **关键读操作走主库**——如提交订单后查订单详情，写完后立即读走主库。(2) **标记法**——写入后在 Redis 中设标记（如 `{user_id}:force_master`，5 秒过期），应用层检测标记决定是否走主库。(3) **半同步复制**——主库等至少一个从库确认收到 binlog 再返回成功，从源头减少延迟窗口。(4) **前端延迟**——写入成功后前端不立即查询，暂停 200-500ms 再请求（用户体验最差，不推荐）。

**加分点**：能根据场景选择方案——金融转账用方案 1，电商商品列表用方案 2，日志数据可以不处理（延迟本来就可接受）。

## Q2：ProxySQL 和 MySQL Router 怎么选？

**考点**：了解工具生态。

**回答**：MySQL Router 是官方出品，免费、轻量、配置简单——适合基础读写分离需求。ProxySQL 功能强大——支持 SQL 级别的路由规则、查询缓存、连接池、故障切换、慢查询统计。如果需要复杂的路由规则（如按表名路由、按用户路由）、查询缓存、详细的监控指标，选 ProxySQL。如果只需要"SELECT 走从库、其他走主库"，MySQL Router 足够。

**加分点**：能说出 ProxySQL 的端口设计——6033 管理端口（配置修改）、6032 数据端口（实际的数据库连接）。ProxySQL 支持在线修改规则无需重启。
