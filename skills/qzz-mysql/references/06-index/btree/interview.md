# 面试题

## Q1：为什么 MySQL InnoDB 用 B+Tree 而不是 B-Tree 或 Hash？

**考点**：最核心的索引面试题。

**回答**：B+Tree 相比 B-Tree，所有数据存在叶子节点，内部节点只存 key——这让每个节点能存更多 key，树更矮，IO 更少。同时叶子节点用链表连接，范围查询极快。相比 Hash——Hash 等值查询 O(1)，但范围查询完全不行。

## Q2：三层 B+Tree 能存多少数据？

**考点**：不只是帮数据——考你对 InnoDB 页大小的理解。

**回答**：以默认 16KB 页大小为例，内部节点存约 1170 个 key，叶子节点存约 16 行。三层 = 1170 × 1170 × 16 ≈ 2000 万行。主键越大（BIGINT vs INT），树越高，存同样数据需要的页越多。
