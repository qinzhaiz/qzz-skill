# 常见错误

## 错误 1：用乐观锁但没处理更新失败

**症状**：偶尔有用户反馈"明明点击了保存，第二天打开发现没保存上"。没有报错日志。

**原因**：乐观锁的 `UPDATE ... WHERE version = ?` 返回 `affected_rows = 0`，应用层没有检查这个值，当成更新成功继续往下走了。

**怎么修**：每次乐观锁 UPDATE 后检查 `affected_rows`（或 `rowCount`）。如果是 0，要么重新读取数据后提示用户，要么自动重试。

## 错误 2：以为乐观锁不需要数据库锁

**症状**：库存扣减用了乐观锁，高峰时重试次数爆炸，CPU 打满。

**原因**：乐观锁的前提是"冲突概率低"。库存扣减冲突概率很高——每秒钟几百个请求抢同一件商品——乐观锁会导致大量更新失败和重试，重试又带来更多冲突，恶性循环。

**怎么修**：高冲突用悲观锁（FOR UPDATE），低冲突用乐观锁（版本号）。反过来就是灾难。

## 错误 3：悲观锁忘了在事务中用 FOR UPDATE

**症状**：用了 BEGIN/COMMIT，也做了 FOR UPDATE，但还是超卖了。

**原因**：FOR UPDATE 只在事务中有效。如果 `autocommit = 1`，执行完 SELECT ... FOR UPDATE 后事务自动提交了，锁立即释放了。后面的判断和更新是另一个事务，锁形同虚设。

**怎么修**：悲观锁必须包在 `BEGIN ... FOR UPDATE ... UPDATE ... COMMIT` 里。检查 `autocommit` 设置。
