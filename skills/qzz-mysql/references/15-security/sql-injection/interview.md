# 面试题

## Q1：什么是 SQL 注入？怎么防御？

**考点**：每个开发者必须能回答的问题。

**回答**：SQL 注入是攻击者通过精心构造的用户输入，改变应用拼接的 SQL 语句的语义，达到非法访问数据目的的攻击方式。核心防御手段是**参数化查询**（Prepared Statement）——把 SQL 结构和数据分离，数据库引擎自动区分代码和数据。辅助手段包括：输入白名单验证、最小权限原则（应用账户不给 DROP/ALTER 权限）、使用 ORM（默认安全的查询构建器）、WAF 防火墙。

**加分点**：能说出参数化查询不能用于 SQL 关键字（ORDER BY、表名、列名）——这些需要白名单验证。能举例说明自己的项目中如何具体实现参数化查询。

## Q2：转义输入和参数化查询有什么区别？为什么后者更好？

**考点**：理解"黑名单 vs 白名单"的安全哲学。

**回答**：转义是"把危险字符（如单引号）替换掉"——这是黑名单思路，永远可能有遗漏（不同编码、新攻击手法）。参数化查询是"数据和代码分离"——数据库在解析 SQL 时就确定了结构，参数值只是数据，不参与 SQL 结构构建。这是白名单思路——所有数据都是安全的。参数化查询更可靠，因为它从根本上消除了注入的可能，而不是试图拦截所有可能的攻击输入。

**加分点**：能说出参数化查询的另一个好处——预编译的 SQL 可以被缓存和重用，性能也更好。能解释为什么 LIKE 查询的参数化也安全——数据库知道 `%` 在参数值中是普通字符。
