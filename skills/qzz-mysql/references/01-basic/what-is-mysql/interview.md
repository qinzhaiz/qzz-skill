# 面试题

## Q1：MySQL 和 PostgreSQL 的区别？

**考点**：看你知不知道除了 MySQL 还有别的数据库，以及有没有实际用过。

**回答**：都是开源的关系型数据库，但重点不同。MySQL 追求简单和快，PostgreSQL 追求 SQL 标准兼容和功能完整性。MySQL 的默认引擎 InnoDB 经过大量读取优化适合 Web 应用，PostgreSQL 在复杂查询、地理数据（PostGIS）、全文搜索方面更强。实际选型取决于业务需求——大多数互联网公司用 MySQL，数据分析和复杂查询场景考虑 PostgreSQL。

**加分**：能说出具体的功能差异——PostgreSQL 支持数组类型、JSONB 索引、窗口函数比 MySQL 早很多年。MySQL 8.0 之后追上来不少，但 PostgreSQL 在这些方面仍然领先。

## Q2：MySQL 的客户端-服务器架构是什么意思？

**考点**：是否理解数据库不是"一个桌面软件"，而是 C/S 架构的服务。

**回答**：MySQL 由两个独立的部分组成。服务器端（`mysqld` 进程）是真正管理数据的一方——它读写数据文件、处理 SQL、控制权限。客户端（命令行、Workbench、Java/Python 程序）是用户交互的一方——它发出 SQL 请求，接收返回结果。客户端和服务器通过网络通信，可以在同一台机器上，也可以分离。

**加分**：举出实际项目中的部署方式——"我们在开发机上本地跑 MySQL，生产环境是一台独立的数据库服务器，应用服务器通过内网 IP 连接数据库服务器，走 3306 端口。"

## Q3：为什么 MySQL 这么流行？

**考点**：不是考历史，是看你对技术选型有没有思考。

**回答**：核心原因——**开源免费 + 简单够用**。LAMP（Linux + Apache + MySQL + PHP）技术栈在 2000 年代推动了 Web 开发的大爆发，MySQL 作为这个组合的一部分被广泛采用。后面 Facebook、Google 等大公司的使用又证明了它的可靠性。到今天，虽然有了更多选择，但 MySQL 的生态（工具、文档、社区）已经非常成熟，学了不亏。

**加分**：提到 MySQL 的不足——"MySQL 早期在 SQL 标准兼容方面确实不如 PostgreSQL，但 8.0 之后加了窗口函数、CTE、JSON 支持，差距在缩小。另一个常见批评是 Oracle 收购后的开源担忧，这催生了 MariaDB 分支。"
