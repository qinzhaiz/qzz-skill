# 面试题

## Q1：线上数据库变慢了，你第一时间做什么？

**考点**：实战思路，不是背操作。

**回答**：第一步不是改配置，而是**找证据**。先看 `SHOW FULL PROCESSLIST`——有没有正在运行的慢查询或锁等待。然后看慢查询日志——找最耗时和最频繁的 SQL。如果没有开慢查询日志，先临时开启（`long_query_time=1`）。找到问题 SQL 后，用 EXPLAIN 分析为什么慢。

**加分点**：能说出"先止血再优化"——遇到大查询占满资源，先 `KILL` 掉，再慢慢分析优化。能提到监控告警——线上应该提前配置好慢查询监控，不用等用户反馈才知道。

## Q2：慢查询日志和 General Query Log 有什么区别？

**考点**：理解各自的用途。

**回答**：慢查询日志只记录**超过时间阈值的 SQL**，用于性能诊断。General Query Log 记录**所有 SQL**（不管快慢），主要用于审计和调试，但对性能影响非常大（所有请求都要写日志），**生产环境绝对不要开**。如果需要审计，用审计插件（Audit Plugin），比 General Query Log 高效。

**加分点**：能说出 Performance Schema 作为第三种选择——比慢查询日志更细粒度（可以按事件类型监控），比 General Log 更高效。
