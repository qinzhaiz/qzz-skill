# 常见错误

## 错误 1：所有环境都用 root 连接

**症状**：应用代码里数据库连接配置写的是 `root`。某天运维误操作 DROP 了一个表，发现是应用库里生产环境的表——原来应用用的是 root。

**原因**：开发环境图方便用了 root，部署到生产时没有改。root 有 ALL PRIVILEGES，可以做任何操作，包括 DROP DATABASE。

**怎么修**：每个应用创建独立账户，只给必需的 CRUD 权限。环境变量或配置中心管理账户信息，不同环境不同账户。

## 错误 2：用 `%` 通配符允许从公网连接

**症状**：`CREATE USER 'app'@'%'`——允许从任何 IP 连接。公网扫描器发现了你的 MySQL 端口，暴力破解密码。

**原因**：`%` 匹配所有 IP 地址。如果 MySQL 暴露在公网（3306 端口），任何人都可以尝试连接。

**怎么修**：限制 IP 范围。内网应用用 `'app'@'10.0.0.%'` 或 `'app'@'172.16.0.0/255.255.0.0'`。本地连接用 `'app'@'localhost'`。如果必须公网，至少搭配防火墙或 VPN。

## 错误 3：给应用账户 GRANT OPTION

**症状**：安全审计发现某个应用账户能把权限授给别人。这意味着应用被攻破后攻击者可以给自己创建后门账户。

**原因**：`GRANT ALL PRIVILEGES ON mydb.* TO 'app'@'%' WITH GRANT OPTION`——WITH GRANT OPTION 允许这个用户把权限转授给其他人。除非是 DBA 账户，否则绝对不要加。

**怎么修**：`REVOKE GRANT OPTION ON mydb.* FROM 'app'@'%';`。应用账户永远不需要 GRANT OPTION。
