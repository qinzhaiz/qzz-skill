# ACID

> ACID 是事务的四个核心特性——原子性、一致性、隔离性、持久性。InnoDB 各用不同的机制实现。

## 四个特性

| 特性 | 含义 | InnoDB 怎么实现的 |
|------|------|-------------------|
| **原子性** (Atomicity) | 事务里的操作要么全成功，要么全回滚 | **undo log** 记录逆向操作 |
| **一致性** (Consistency) | 事务前后数据满足所有约束 | 约束 + 原子性+隔离性+持久性共同保证 |
| **隔离性** (Isolation) | 并发事务互不干扰 | **锁 + MVCC** |
| **持久性** (Durability) | 提交后数据永久保存，重启也不丢 | **redo log** 崩溃恢复 |

## 原子性 —— 要么全做，要么全不做

事务中途失败 → InnoDB 通过 **undo log** 回滚。undo log 记录了"逆向操作"——INSERT 记 DELETE，UPDATE 记旧值。回滚时按 undo log 的逆序恢复数据。

## 一致性 —— 数据始终符合规则

这是 ACID 里最"虚"的一个——它大部分由其他三个 + 数据库约束（主键、外键、NOT NULL、UNIQUE）共同保证。InnoDB 本身不单独实现一致性，它是 ACID 组合的结果。

## 隔离性 —— 互不干扰

两个事务同时操作同一行数据——InnoDB 通过 **锁 + MVCC** 让它们感觉不到对方。

[隔离级别一节](../isolation/)专门讲。

## 持久性 —— 提交了就不会丢

事务 COMMIT 后，即使立刻断电，重启后数据还在——InnoDB 用 **redo log** 保证。redo log 是物理日志——记录"在数据页 X 偏移 Y 写入了 Z"。写 redo log 是顺序写，很快。

[执行流程一章](../../09-execution/redo-undo-log/)会详细讲 redo log 和两阶段提交。

## 注意事项

- **ACID 不是免费的。** 事务和锁带来并发性能代价——隔离级别越高，并发性越低。
- **MyISAM 完全不支持 ACID。** 没有事务，没有崩溃恢复。这就是为什么默认引擎是 InnoDB。
