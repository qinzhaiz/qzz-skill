# 练习

## 基础练习

1. 写一段 Python/Java 代码，演示 SQL 注入攻击：拼接用户输入后查询数据库。然后用参数化查询改写，验证攻击无效。

2. 解释为什么 `ORDER BY {column}` 不能参数化。给出安全的替代方案。

## 进阶练习

1. 在你的测试数据库中执行 MySQL 的 `PREPARE ... EXECUTE` 语句，理解参数化查询在数据库层的工作原理。

2. 给你的项目代码做一次 SQL 注入检查——搜索所有拼接 SQL 字符串的地方（`f"SELECT"`, `"+"` 等），评估是否需要修改。

## 答案

1. 拼接版本中 `' OR '1'='1` 成功绕过。参数化版本中同样的输入被当作普通字符串。原理是预编译时 SQL 结构已固定，参数只提供数据值。

2. `ORDER BY` 是 SQL 关键字，参数化只能绑定数据值，不能绑定 SQL 结构。安全替代：白名单——只接受预定义的合法列名（如 `['id', 'name', 'created_at']`），拒绝其他输入。

3. `PREPARE` 在数据库服务器端先解析 SQL 结构，`EXECUTE ... USING` 传入的参数被当作纯数据（不是 SQL 代码），所以无法改变 SQL 语义。

4. 重点搜索：字符串拼接（`+`, `f-string`, `format()`）、原生 SQL 调用（`raw()`, `execute()` 直接拼接）。检查这些输入源是否来自用户。优先改为 ORM 方法的参数化写法。
