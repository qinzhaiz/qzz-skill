# 常见错误

## 错误 1：慢查询 = 加索引

**症状**：每次遇到慢查询就加索引，表上堆积了几十个索引。

**原因**：没有分析慢的根本原因——可能是 SQL 写法有问题、锁等待、数据量真的超了硬件极限。盲目加索引会让写入越来越慢。

**怎么修**：先看 EXPLAIN——确认真的是全表扫。再看慢查询日志——定位具体的 SQL。确认是需要索引而不是其他原因。加完验证。

## 错误 2：性别、状态这些列也建索引

**症状**：`CREATE INDEX idx_gender ON user(gender)`——只有 2-3 个不同值的列。

**原因**：以为"所有 WHERE 列都该建索引"。

**怎么修**：区分度极低的列（不到 10%）不用建索引——它只能筛掉一半数据，全表扫可能更快。MySQL 优化器也可能直接忽略这个索引。

## 错误 3：从不清理索引

**症状**：两年的表，堆了 15 个索引，大部分是早期试错建的，不知道哪些还在用。

**原因**：建索引容易，删索引不敢——怕影响线上。

**怎么修**：定期查 `sys.schema_unused_indexes`，删除从未用过的索引。用 EXPLAIN 验证删除后常用查询不受影响。
