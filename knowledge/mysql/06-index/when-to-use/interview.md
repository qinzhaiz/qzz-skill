# 面试题

## Q1：什么列不该建索引？举三个例子。

**考点**：知道建，也要知道不建。

**回答**：区分度极低的列（性别、布尔值）——只能分一半，全表扫不慢。频繁更新的列——每次 UPDATE 都要维护索引，代价 > 收益。很少查询的列——建了没人用，浪费空间和写入成本。

## Q2：你怎么判断一个查询是不是该加索引？

**考点**：完整的工作流。

**回答**：先用慢查询日志定位具体 SQL → EXPLAIN 看执行计划（key 是否为 NULL、rows 是否过大）→ 如果确实是全表扫，分析 WHERE/JOIN/ORDER BY 列 → 设计合适的索引（单列或联合）→ 加索引后用 EXPLAIN 验证 rows 显著减少。
