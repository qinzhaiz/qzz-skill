# 面试题

## Q1：InnoDB 和 MyISAM 的核心区别是什么？

**考点**：必须要能答出来的基础题。

**回答**：四个核心区别——(1) **事务**：InnoDB 支持 ACID，MyISAM 不支持。(2) **锁粒度**：InnoDB 用行锁，MyISAM 只有表锁——写入并发能力差距巨大。(3) **崩溃恢复**：InnoDB 有 redo log，崩溃后自动恢复；MyISAM 崩溃可能丢数据，需要手动 REPAIR TABLE。(4) **索引结构**：InnoDB 是聚簇索引（数据存在主键索引叶子节点），MyISAM 数据和索引分开存储（索引叶子节点存行指针）。

**加分点**：能说出 MySQL 8.0 中 MyISAM 已过时，system tables 也全部换为 InnoDB。能阐述"表锁 vs 行锁"对并发性能的影响——MyISAM 一个写操作阻塞所有读写，InnoDB 不同行可并行。

## Q2：为什么 InnoDB 的 COUNT(*) 比 MyISAM 慢？怎么优化？

**考点**：MVCC 对性能的影响。

**回答**：MyISAM 维护了表的精确行数变量，COUNT(*) 直接读这个变量（O(1)）。InnoDB 有 MVCC——不同事务可能看到不同的行数（取决于事务的隔离级别和 ReadView），所以不能维护一个"所有连接都能用的"精确值。每次 COUNT(*) 都要扫描索引来计数。优化方案：(1) 不要求精确值时用 `SHOW TABLE STATUS` 或 `EXPLAIN` 的估算值，(2) 单独维护计数器（Redis、计数表），(3) 如果必须精确且表很大，走最小索引而非主键。

**加分点**：能解释为什么 InnoDB 自动走最小索引（主键索引叶子节点有完整行数据，二级索引只有索引列+主键，二级索引页更小，扫描更快）。
