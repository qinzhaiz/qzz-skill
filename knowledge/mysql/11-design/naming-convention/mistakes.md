# 常见错误

## 错误 1：表名用复数

**症状**：团队的一半人建表用单数（`user`），一半人用复数（`users`），代码里混着写。

**原因**：没有统一的规范。有些 ORM 默认用复数生成表名（Laravel），有些用单数（Django）。

**怎么修**：统一用单数。表是实体的集合，但命名应该反映"每一行是什么"。`user` 表里的每一行是一个用户，不是"多个用户"。参考 MySQL 自带的系统表：`information_schema.tables` 不叫 `tables`。

## 错误 2：用 utf8 而不是 utf8mb4

**症状**：用户输入 emoji 表情（如 😀）保存失败，报错 `Incorrect string value`。

**原因**：MySQL 的 `utf8` 字符集最大只支持 3 字节的 UTF-8 字符，emoji 是 4 字节的。这是 MySQL 的历史遗留问题——真正的 UTF-8 是 `utf8mb4`。

**怎么修**：建库、建表、建字段都用 `utf8mb4`，排序规则用 `utf8mb4_unicode_ci`（更准确的排序）或 `utf8mb4_general_ci`（更快但不够准确）。

## 错误 3：字段不给 COMMENT

**症状**：接手一个老旧数据库，几百张表，大部分字段没有注释。看代码才知道 `flag` 是干什么的。

**原因**：写的时候觉得"字段名够清晰了"，三个月后自己都忘了当时的业务含义。特别是枚举值（`status: 0/1/2`），不写注释就是密码本。

**怎么修**：每个字段都写 COMMENT，特别是状态字段——`COMMENT '状态：0待审核 1已通过 2已拒绝'`。这不仅帮助同事，也帮助三个月后的自己。
