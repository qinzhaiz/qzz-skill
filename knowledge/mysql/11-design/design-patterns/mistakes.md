# 常见错误

## 错误 1：大批量用 EAV 模式

**症状**：200 万种商品，每种有 10-50 个属性，product_attr 表有 5000 万行。查"内存 > 8GB 的手机"慢如蜗牛。

**原因**：EAV 把所有属性打平在一张长表里，查询需要多次自连接（一个属性一次 JOIN），而且无法对值做类型检查（"128GB" 和 "红色" 都是 VARCHAR，无法区分）。

**怎么修**：MySQL 8.0 用 JSON 列存可变属性，配合虚拟列 + 虚拟列索引优化高频查询。如果属性非常多且查询复杂，考虑 ES 做搜索，MySQL 做主存储。

## 错误 2：软删除后唯一索引冲突

**症状**：用户 A 删除了账号，新用户想用同样的用户名注册，报 duplicate key 错误。

**原因**：唯一索引 `uk_username` 包含所有行（包括软删除的），即使 `is_deleted = 1`，username 也不能重复。

**怎么修**：(a) 把唯一索引改成 `(username, is_deleted)` 但这样同一个 username 可以有一条活跃和一条已删除——还是有问题，(b) 删除时把 username 改成 `{id}_{deleted}_{原username}`，释放唯一占位，(c) 不用软删除，直接真删除（如果业务允许）。
