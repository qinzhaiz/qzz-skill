# 面试题

## Q1：大表怎么做分页？OFFSET 很大时怎么办？

**考点**：每个人都会遇到的问题。

**回答**：OFFSET 很大时慢是因为 MySQL 需要扫描 OFFSET+LIMIT 行然后丢弃前面。两种解决方案：(1) **基于游标的分页**（推荐）——前端记住上一页最后一条的主键，下一页用 `WHERE id > last_id ORDER BY id LIMIT n`。缺点是不能跳页。(2) **覆盖索引 + JOIN**——先用覆盖索引找到目标 ID，再 JOIN 回表取完整行。`SELECT * FROM t JOIN (SELECT id FROM t ORDER BY id LIMIT offset, n) tmp ON t.id = tmp.id`。

**加分点**：能说出两种方案的适用场景——API 分页用方案 1（无限滚动），后台管理需要跳页用方案 2。能提到 Elasticsearch 等搜索引擎做复杂分页。

## Q2：怎么判断一个索引该不该加？

**考点**：不是"慢就加索引"。

**回答**：三个判断标准——(1) 这个查询的执行频率高不高？每天执行一次的报表慢 10 秒可以接受，每秒执行 1000 次的接口慢 0.1 秒不行。(2) 加索引后查询快了多少？用 EXPLAIN 对比加索引前后的 type 和 rows。(3) 写入代价能不能接受？被索引的列如果经常 UPDATE，索引维护开销大。对高频写入的表（如日志、流水表），索引要尽可能精简。

**加分点**：能提到"联合索引比多个单列索引更优"的原则——`(a, b)` 的联合索引可以覆盖 `WHERE a = 1` 和 `WHERE a = 1 AND b = 2` 两种场景。
