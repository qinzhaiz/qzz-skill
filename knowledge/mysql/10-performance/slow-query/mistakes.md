# 常见错误

## 错误 1：生产环境 `long_query_time = 0`

**症状**：开了慢查询后，数据库反而变卡了。

**原因**：`long_query_time = 0` 意味着**记录所有查询**。高并发下每秒几千次查询，每个都要写日志（磁盘 IO），日志文件迅速膨胀（几 GB 每小时），磁盘 IO 被日志写满，数据库变慢。

**怎么修**：生产环境 `long_query_time` 至少设 0.1-1 秒。如果真的需要记录所有查询，用 Performance Schema 或审计插件（更高效）。

## 错误 2：只看平均执行时间

**症状**：`mysqldumpslow -s t` 只看最慢的，忽略了执行次数最多的慢查询。

**原因**：一条执行 1 万次、每次 0.2 秒的查询，总耗时 2000 秒——比一条执行 10 次、每次 10 秒的查询（总耗时 100 秒）影响大 20 倍。但按平均时间排序你只看到 10 秒那条。

**怎么修**：用 `mysqldumpslow -s c`（按次数排序）和 `-s ct`（按总耗时排序）。pt-query-digest 已经按总耗时排好了。

## 错误 3：忽略锁等待时间

**症状**：慢查询日志显示某条查询很慢，但用 EXPLAIN 看 SQL 明明走了索引。

**原因**：`Lock_time` 占了大部分时间。SQL 本身不慢，是被其他事务的锁阻塞了。优化 SQL 没用，要解决锁争用问题。

**怎么修**：分析慢查询时同时看 `Query_time` 和 `Lock_time`。如果 Lock_time 占比高，查 `SHOW ENGINE INNODB STATUS` 和 `information_schema.innodb_trx` 排查长事务和锁争用。
