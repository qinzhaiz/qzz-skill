# 常见错误

## 错误 1：以为 EXPLAIN 的结果就是最终执行计划

**症状**：EXPLAIN 显示用了索引，实际执行时却全表扫描。

**原因**：EXPLAIN 显示的是"预计"计划，不是"实际"执行。如果统计信息不准（比如表数据量变化后没有更新统计），优化器可能选了看起来最优但实际上很差的路。

**怎么修**：定期执行 `ANALYZE TABLE` 更新统计信息。用 `EXPLAIN ANALYZE`（MySQL 8.0.18+）看实际执行情况，包括实际扫描行数和耗时。

## 错误 2：优化器选了全表扫描而不是用索引

**症状**：明明给 WHERE 条件的列建了索引，EXPLAIN 却显示 `type=ALL`。

**原因**：可能的情况——(1) 统计数据认为全表扫描更快（表小或大部分行都满足条件），(2) 索引列使用了函数导致索引失效，比如 `WHERE YEAR(create_time) = 2024`，(3) 隐式类型转换，比如 `WHERE phone = 13800000000` 但 phone 是 VARCHAR。

**怎么修**：检查 SQL 有没有在索引列上做计算或类型转换。用 `EXPLAIN FORMAT=JSON` 看代价评估。如果确定优化器选错了，可以用 `FORCE INDEX` 强制走索引。
