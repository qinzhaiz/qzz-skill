# 面试题

## Q1：XtraBackup 的热备份原理是什么？为什么备份时不锁表？

**考点**：理解物理备份的原理。

**回答**：XtraBackup 不是简单的"复制文件"。它做了三件事：(1) 开始备份时记录当前的 LSN（redo log 位置），(2) 多线程复制 .ibd 文件到备份目录，(3) 启动一个后台线程持续监控 redo log——复制过程中如果有新的写入，这些变更会通过 redo log 记录下来。备份完成后，备份目录中包含了"某个时间点的数据文件 + 备份期间的 redo log"。恢复时通过 prepare 阶段（类似崩溃恢复）把 redo log 应用到数据文件上，得到一个一致的数据快照。

**加分点**：能解释为什么不需要锁表——InnoDB 的 redo log 保证了任何时刻都能通过"数据文件 + redo log"恢复到一致状态。XtraBackup 利用了这一点，在复制过程中不用阻止写入。

## Q2：XtraBackup 和 mysqldump 各适合什么场景？

**考点**：工具选型。

**回答**：XtraBackup 适合大数据库（> 10GB）——备份快、恢复快、支持增量备份，但对 InnoDB 专用，跨大版本恢复可能有问题。mysqldump 适合中小数据库（< 10GB）——简单、灵活、跨版本兼容、可以手动编辑 SQL 恢复部分数据。典型策略：大数据库用 XtraBackup 做全量+增量备份（每天），mysqldump 导出表结构（以防万一），binlog 做时间点恢复（高频）。

**加分点**：能说出"在从库做备份"的最佳实践——无论用哪种工具，尽量在从库执行备份，不影响主库。
