# 面试题

## Q1：误删了一张表，怎么恢复？

**考点**：完整的恢复思路，不是背命令。

**回答**：第一步是**止损**——立刻停止对该表的写入，防止新数据覆盖问题。如果在从库发现，立即 `STOP SLAVE` 保留从库当前的 relay log。第二步**确定恢复目标**——找到最近的全量备份和包含误删操作的 binlog 文件。第三步**在隔离环境恢复**——用全量备份恢复 + binlog 回放到误删前一刻，验证数据正确。第四步**导回生产**——从恢复环境导出被删的表，导入回主库。

**加分点**：能说出几层防护——(1) 如果有延迟从库（延迟回放，如 1 小时），直接从延迟从库恢复最快，(2) 如果是单表，用 `FLASHBACK` 工具生成反向 SQL，(3) 如果全量备份太老，binlog 太多，恢复时间会很长的预估。

## Q2：RPO 和 RTO 分别是什么？怎么确定备份策略？

**考点**：从业务需求反推技术方案。

**回答**：RPO 是能接受的数据丢失量（最多丢多长时间的数据），RTO 是能接受的恢复时长（恢复服务最长需要多久）。这两个指标决定了备份策略：(1) RPO < 1 小时 → 需要实时 binlog 备份或半同步复制，(2) RPO < 1 天 → 每天全量备份，(3) RTO < 30 分钟 → 必须用 XtraBackup + 温备实例 + 自动化恢复脚本，(4) RTO < 4 小时 → XtraBackup + 手动恢复可行。

**加分点**：能举例——金融系统 RPO = 0（不允许丢数据），需要半同步复制 + binlog 实时备份。博客系统 RPO = 1 天（每天备份就行），RTO = 8 小时（反正是内容站，恢复慢一点也可以接受）。
