# 常见错误

## 错误 1：在生产库直接 ALTER 大表

**症状**：执行 ALTER TABLE 后网站挂了——所有请求都在等这个操作完成。

**原因**：MySQL 8.0 之前多数 ALTER 操作需要拷贝整张表，期间表被锁定无法写入。数据量大 = 锁的时间长 = 服务不可用。

**怎么修**：学习阶段随便改。生产环境永远用 pt-online-schema-change 或 gh-ost——它们建一张新表、在新表上改结构、慢慢同步数据、最后切换。全程不锁原表。记一个原则：生产库改结构 = 高风险，先备份再小心操作。

## 错误 2：MODIFY vs CHANGE 分不清

**症状**：只想改列类型，不小心连列名也改了。

**原因**：CHANGE 要求同时指定新旧列名——即使你不想改列名也要写两遍。

**怎么修**：不需要改名时用 MODIFY；需要改名时用 CHANGE。MODIFY 更安全——少一个参数就少一个出错机会。

## 错误 3：新增列忘了设 DEFAULT

**症状**：ALTER TABLE 加了一个 NOT NULL 列但没设 DEFAULT，操作直接报错——表中已有数据在这列上该填什么？。

**原因**：已有行在新列上没有值。如果不设默认值且列是 NOT NULL，MySQL 不知道填什么。

**怎么修**：加 NOT NULL 列时务必设 DEFAULT。
