# 常见错误

## 错误 1：所有列都允许 NULL

**症状**：建表时从来不写 NOT NULL，然后在代码里到处判断 `if result is None`。

**原因**：不知道 NULL 的含义——它表示"未知"，和空字符串、0 都不是一回事。`SELECT * FROM user WHERE age = NULL` 永远不返回结果（NULL 不等于任何东西，包括它自己）。

**怎么修**：建表时明确哪些列必填（NOT NULL），哪些可选。区分 NULL 和空字符串——名字可以为空串，但必须有一个值（NOT NULL DEFAULT ''）。

## 错误 2：忘了设主键

**症状**：表建好了才发现没有主键，数据重复没法区分。

**怎么修**：（上一节讲过，这里补充一点）即使你的表暂时不需要"唯一标识一行"，也应该加一个自增 ID 做主键。InnoDB 需要主键来确定数据的物理存储顺序。

## 错误 3：外键不建索引

**症状**：`FOREIGN KEY (user_id) REFERENCES user(id)` 建了，但没单独在 user_id 上建索引，JOIN 查询越来越慢。

**原因**：外键字段不会自动创建索引——需要手动 `CREATE INDEX`。

**怎么修**：外键列单独建索引。后面学到 [06-index/](../../06-index/) 会详细讲。
