# 常见错误

## 错误 1：所有字符串都设 VARCHAR(255)

**症状**：不管实际存什么，一律 `VARCHAR(255)`。

**原因**：VARCHAR(255) 是很多教材的默认值，大家复制粘贴懒得改。

**怎么修**：根据实际业务设值。姓名 VARCHAR(50)，手机号 VARCHAR(20)，地址 VARCHAR(200)。虽然 VARCHAR 只占用实际内容的长度，但优化器有时会根据定义的最大长度分配内存——没必要浪费。

## 错误 2：用 FLOAT/DOUBLE 存金额

**症状**：财务报表里出现诡异的小数误差（比如总数是 99.999998 而不是 100）。

**原因**：浮点数在计算机里是二进近似值，十进制小数无法精确表示。

**怎么修**：金额用 `DECIMAL(10,2)` 或在代码里用"分"做最小单位存 INT。前者在 SQL 里直接可读，后者在代码层面更灵活。

## 错误 3：DATE 和 DATETIME 混用

**症状**：只存了日期但后来发现需要精确到时分秒，或者存了 DATETIME 但大部分查询只关心日期部分。

**原因**：建表时没想清楚"这个字段需要多精确"。

**怎么修**：问自己：这个数据以后会不会需要按小时/分钟查询？如果会，用 DATETIME。如果只按天查（如生日、注册日期），用 DATE 省空间。
