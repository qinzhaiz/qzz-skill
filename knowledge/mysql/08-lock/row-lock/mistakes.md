# 常见错误

## 错误 1：WHERE 没走索引导致锁全表

**症状**：一个简单的 UPDATE，把其他所有写操作都堵住了。

**原因**：WHERE 条件用的列没有索引 → 全表扫描 → InnoDB 把扫描到的每一行都锁了 → 相当于表锁。

**怎么修**：确认 WHERE 条件有索引。用 `EXPLAIN` 看执行计划，`type=ALL` 就是全表扫描。加索引后锁范围从几千行变成几行。

## 错误 2：把易冲突操作放在事务开头

**症状**：事务中先 UPDATE 了热点行，后面做了很多耗时操作才 COMMIT——锁持有时间太长。

**原因**：两阶段锁协议——锁在事务提交时才释放。如果把热点行更新放在事务开头，那整个事务期间其他人都不能碰这行。

**怎么修**：事务中把热点操作尽量往后放。`BEGIN → 非冲突操作 → 非冲突操作 → 热点更新 → COMMIT`。或者把长事务拆成多个短事务。

## 错误 3：在 RC 级别下期望间隙锁防幻读

**症状**：隔离级别是 READ COMMITTED，期望 `FOR UPDATE` 防幻读——没用。

**原因**：间隙锁只在 RR 级别生效。RC 级别只有 Record Lock（锁行不锁间隙），无法阻止其他事务插入新行。

**怎么修**：如果需要防幻读，用 RR 级别。如果已经是 RC 且需要间隙锁，考虑在应用层处理或升级隔离级别。
