# 常见错误

## 错误 1：在事务中执行非数据库操作

**症状**：简单查询把整张表堵死了。

**原因**：在事务中查完数据库后又调了外部 API、发了邮件、做了 Redis 操作——事务迟迟不提交，MDL 读锁一直不释放。此时任何 DDL 都排不上队，后面的 DML 也跟着堵。

**怎么修**：事务只做数据库操作。调外部服务放在事务外。`BEGIN` 和 `COMMIT` 之间只放 SQL。

## 错误 2：对大表直接执行 ALTER TABLE

**症状**：执行 `ALTER TABLE` 后，所有读写都超时。

**原因**：ALTER TABLE 需要 MDL 写锁，而当时刚好有长事务持有 MDL 读锁。ALTER 等了很久终于执行（复制整张表），期间后面的请求全排队。

**怎么修**：
1. 改表前先查 `information_schema.innodb_trx` 确认没有长事务
2. 用 `pt-online-schema-change` 等工具在不下锁的情况下改表
3. MySQL 8.0 用 `ALGORITHM=INSTANT` 尽可能避免复制表

## 错误 3：以为 MDL 只在语句执行期间持有

**症状**：明明只是一个 SELECT，锁怎么一直不释放？

**原因**：MDL 的释放时机是**事务提交**，不是**语句结束**。即使是 `SELECT * FROM user` 这条简单查询，只要在事务中，事务不提交 MDL 就不释放。

**怎么修**：用了 BEGIN 就要记得 COMMIT。配置 `autocommit=1` 的简单语句没这个问题——每条语句自动提交。
