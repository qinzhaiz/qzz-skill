# 常见错误

## 错误 1：应用层不处理死锁重试

**症状**：高并发下偶尔出现死锁报错，用户看到 500 错误。

**原因**：死锁在并发环境中难免发生，InnoDB 检测到后会回滚一个事务。但应用层没有重试逻辑，这个事务的操作就丢失了。

**怎么修**：所有事务操作都要捕获死锁异常（MySQL 错误码 1213）并重试。重试次数 3 次即可，配合指数退避。

## 错误 2：无序更新导致死锁

**症状**：所有请求都是 `UPDATE user SET balance = balance - 1 WHERE id = ?`，没有任何冲突，但高并发时仍然死锁。

**原因**：虽然每个语句看起来不同，但如果索引扫描范围重叠，间隙锁之间也会形成等待环。或者同一事务中更新多行，不同事务的更新顺序不一致。

**怎么修**：一个事务如果必须更新多行，**固定更新顺序**。比如都按 id 升序更新——`UPDATE ... WHERE id = 小 → UPDATE ... WHERE id = 大`。

## 错误 3：事务太大导致死锁

**症状**：死锁频率和事务大小成正比。

**原因**：事务越大 → 持有的锁越多 → 锁的持有时间越长 → 和别人发生冲突的概率成倍增加。

**怎么修**：拆大事务为小事务。每个事务只做一件事。业务逻辑不要包在一个大 BEGIN/COMMIT 里。
