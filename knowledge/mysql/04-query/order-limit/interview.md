# 面试题

## Q1：大偏移量分页怎么优化？

**考点**：项目经验。面试官想确定你真的在生产环境写过 SQL。

**回答**：用游标分页（keyset pagination）替代 OFFSET。记住上一页最后一条的主键值，下一页用 `WHERE id > last_id ORDER BY id LIMIT n`。每次都走索引，无论翻到第几页速度一样。代价是不能跳页。

**加分**：能说出其他方案——"Elasticsearch 的 search_after、Redis 的有序集合也能帮前端做分页。更极端的情况在应用层缓存热门页的前几页数据。"

## Q2：ORDER BY 的列需要建索引吗？

**考点**：索引知识 + 排序的结合。

**回答**：视情况。如果排序和 WHERE 能共用同一个索引——不需要额外排序。但如果排序列和过滤列不在同个索引中，MySQL 会做 filesort（在内存或磁盘上排序）。大表上 filesort 很慢。总结：经常排序的列值得建索引。
