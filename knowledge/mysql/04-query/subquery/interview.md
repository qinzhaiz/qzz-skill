# 面试题

## Q1：EXISTS 和 IN 的区别？什么时候用哪个？

**考点**：不是背语法，是理解执行原理。

**回答**：IN 先跑内层查询，拿结果集跑外层。适合内层结果集小的场景。EXISTS 外层每行跑一次内层——但内层有索引时就会很快。通常：外层表小用 EXISTS，内层结果集小用 IN。MySQL 8.0 的优化器已经能在很多场景下自动转换。

**加分**：提到 NOT IN 的 NULL 陷阱 + NOT EXISTS 不受 NULL 影响。

## Q2：子查询和 JOIN 的性能差异？

**考点**：实际项目经验。

**回答**：MySQL 5.7 子查询优化差，很多场景下 JOIN 显著更快。8.0 大幅改善了子查询优化（支持 semi-join、materialization），很多简单子查询性能和 JOIN 相当。但复杂的多层嵌套子查询仍然推荐改写为 JOIN 或 CTE。
