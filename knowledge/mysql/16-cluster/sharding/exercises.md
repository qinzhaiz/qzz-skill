# 练习

## 基础练习

1. 用自己的话解释：什么是分片键？为什么它的选择如此重要？

2. 设计一个用户表的分片方案：1 亿用户，按 user_id 分 8 个库，每个库 4 张表。写出分片算法。

## 进阶练习

1. 用 Docker 搭建 ShardingSphere-Proxy + 2 个 MySQL 节点，配置分片规则，验证"带分片键"和"不带分片键"的查询差异。

2. 讨论：订单表按 `user_id` 分片后，商家想看自己所有订单怎么办？

## 答案

1. 分片键决定数据分布。选得好：均匀分布、查询都带分片键、性能线性扩展。选不好：热点集中在某几个分片、大量查询需要广播、性能反而不如单机。

2. 库 = user_id % 8，表 = user_id / 8 % 4。user_id=12345：库=12345%8=1，表=12345/8%4=1543%4=3 → ds1.user_3。

3. 带分片键查询走精确路由（1 条 SQL），不带分片键查询广播到所有分片（32 条 SQL）。性能差距巨大。

4. 商家查订单不带 user_id → 广播查询不可接受。方案：(a) 再建一套按 merchant_id 分片的订单数据（双写或数据同步），(b) 用 ES 做搜索层，MySQL 做主存储，(c) 商家端业务量不大时，商户 ID 表独立存储（不参与分片）。
