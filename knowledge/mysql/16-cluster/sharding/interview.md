# 面试题

## Q1：什么时候需要分库分表？单表多大该分？

**考点**：不是背数字，是理解判断标准。

**回答**：没有绝对的阈值。判断标准：(1) 索引优化、缓存、读写分离都做了，仍然达不到性能要求；(2) 单表数据量导致运维困难（DDL 无法执行、备份太慢）；(3) 磁盘容量不足。经验值：单表 > 1000 万行 或 > 10GB 开始关注，> 5000 万行认真评估。但很多业务永远到不了这个量级——大多数创业公司不需要分库分表。

**加分点**：能列出分库分表前的优化清单——索引优化、SQL 优化、缓存、读写分离、垂直拆分。说明分库分表是"最后手段"。

## Q2：分片键怎么选？

**考点**：分片设计的核心。

**回答**：三个原则——(1) 大部分查询都带这个字段，(2) 数据分布均匀，(3) 避免跨分片 JOIN 和事务。通常选 user_id 或 order_id。注意：选 user_id 的好处是用户维度的查询都精确路由，坏处是商家、平台维度的查询要广播。

**加分点**：能说出"查询模式驱动分片设计"——先梳理核心业务查询，再决定分片键。如果查询模式冲突（用户维度和商家维度都需要高效率），考虑异构数据（双写或多数据源）。
