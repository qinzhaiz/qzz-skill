# 常见错误

## 错误 1：把复制当高可用

**症状**：搭了主从复制就以为高可用搞定了。主库真挂了才发现——没有自动切换，手动切换花了 15 分钟，服务全挂。

**原因**：复制是数据冗余，不是服务可用。没有故障检测和自动切换机制 = 没有高可用。

**怎么修**：至少配置监控告警 + 切换预案文档。生产环境上 MHA、Orchestrator 或 InnoDB Cluster。

## 错误 2：脑裂——双主写入

**症状**：网络分区恢复后，发现两个"主库"各有一批新写入，数据冲突无法解决。

**原因**：故障切换工具误判主库宕机（实际是网络问题），提升从库为新主库。原主库仍在接受写入。两个库的数据分叉了。

**怎么修**：用有防脑裂机制的方案——Group Replication 的 Paxos 只允许 majority 组写入。或设置 `group_replication_unreachable_majority_timeout` 自动踢出失联节点。

## 错误 3：自动切换配了但从来没演练过

**症状**：自动切换配置正确，但从来没实测过。真出问题时才发现 SSH key 过期了、脚本报错了、数据丢了。

**原因**：没有定期做故障演练。HA 方案需要持续的维护和验证。

**怎么修**：每季度至少做一次故障切换演练，记录切换耗时和数据完整性检查结果。
